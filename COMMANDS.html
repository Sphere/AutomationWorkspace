Aastrika Automation — Command Reference

Everything needed to run the three Playwright suites and to keep them in Git.

Shell examples are PowerShell (the default on these machines). Where a command needs an environment variable, the bash equivalent is given alongside, because the syntax differs and getting it wrong silently runs the wrong environment.

SuitesSphereWebAutomation, EkshamataWebAutomation, CBPAutomation
RootD:\Automation
Noderun every command from inside a suite folder, never from D:\Automation
Run commands from the suite folder. npx playwright test executed at D:\Automation finds no config and every spec fails. cd into SphereWebAutomation, EkshamataWebAutomation or CBPAutomation first.

What is tracked, and what never is

Tracked on purpose — the throwaway @yopmail.com account ledgers, so the team shares one history of which accounts exist where:

text
EkshamataWebAutomation/  created-users.txt, last-created-user.json,
                         email-counters.json, test-reports/credentials_*.csv
SphereWebAutomation/     config/accounts.json, registered-accounts.xlsx,
                         generated-emails.txt, .last-registered-email.json

Never tracked:

ExcludedWhy
.env (all three)API tokens, SMTP password, Gemini key, portal credentials
.auth-state*.json, .auth/live session cookies
test-reports/, compare-reports/, regression-results/, reports/, playwright-report/, test-results/regenerated every run, thousands of files
node_modules/reinstallable
*copy*.json, nulstray duplicates from a file copy or a shell redirect

The credentials_*.csv files are an exception carved out of an ignored directory. That needs test-reports/* rather than test-reports/, because Git cannot re-include a file whose parent directory is excluded.

2. Git and GitHub

Daily loop

powershell
cd D:\Automation\SphereWebAutomation

git status                      # what changed
git status --short               # the same, compact
git diff                         # unstaged changes
git diff --cached                # what is staged

git add -A                       # stage everything not ignored
git commit -m "Fix the T&C gate detection"
git push

git add -A is safe here: the .gitignore files keep credentials and run output out. Verify with section 2.4 before any commit that touches new files.

Pull before you push

powershell
git pull --rebase                # replay your commits on top of the remote
git log --oneline --graph -10     # see the shape of the history

First-time setup for a new clone

powershell
git clone https://github.com/Santhoshshivaprakash/SphereWebAutomation.git
cd SphereWebAutomation
npm install
npx playwright install chromium
Copy-Item config\accounts.example.json config\accounts.json   # then fill it in

.env is not in the repo. Copy .env.example where one exists (e-kshamata, CBP) and fill in the tokens, or ask for the values.

2.4 Check what you are about to publish

Run this before committing new files. It catches a credential file that no .gitignore rule covers yet.

powershell
# filenames that look sensitive
git diff --cached --name-only | Select-String -Pattern "\.env|auth-state|secret|token|cookie"

# actual secret VALUES in staged content
git diff --cached --name-only | ForEach-Object { Select-String -Path $_ -Pattern "eyJ[A-Za-z0-9._-]{30,}|AIza[0-9A-Za-z_-]{30,}|bearer [A-Za-z0-9._-]{20,}" }

bash equivalent:

bash
git diff --cached --name-only | grep -iE "\.env|auth-state|secret|token|cookie"
git diff --cached --name-only -z | xargs -0 grep -ohE "eyJ[A-Za-z0-9._-]{30,}|AIza[0-9A-Za-z_-]{30,}"

Adding a remote to a suite that has none

powershell
git init
git symbolic-ref HEAD refs/heads/main      # name the branch main
git add -A
git commit -m "Initial commit"
git remote add origin https://github.com/Santhoshshivaprakash/<REPO>.git
git push -u origin main

2.6 Situations you will actually hit

The GitHub repo was created with a README, so the push is rejected. The histories are unrelated. Merge the stub in rather than force-pushing over it:

powershell
git fetch origin main
git merge origin/main --allow-unrelated-histories
# conflict on README.md — keep the project one:
git checkout --ours README.md
git add README.md
git commit --no-edit
git push -u origin main

A file is ignored but you want it tracked from now on. Delete the rule from .gitignore — do *not* use git add -f. A force-add stages the file once and then goes quiet as the suite appends to it.

powershell
# remove the line from .gitignore, then
git add -A
git commit -m "Track the account ledger"

git check-ignore says a file is not ignored, but the rule is clearly there. A file already in the index is never reported as ignored. Take it out first:

powershell
git rm --cached "path\to\file"
git check-ignore -v "path\to\file"        # now it reports the matching rule

**A negation like !test-reports/credentials_*.csv does nothing.** Two possible causes, both real:

credentials_*.csv further down overrides the negation above it.

  1. the parent directory is excluded — change test-reports/ to test-reports/*;
  2. a broader rule appears later in the file and wins — a bare
powershell
git check-ignore -v test-reports\credentials_x.csv    # prints the rule and line number

Something sensitive was committed. It is in history even after deleting the file. Remove it from tracking, then treat the credential as exposed and rotate it:

powershell
git rm --cached path\to\secret
# add it to .gitignore, then
git commit -m "Stop tracking <file>"

Undo, safely.

powershell
git restore path\to\file          # discard unstaged changes to one file
git restore --staged path\to\file  # unstage, keep the edit
git reset --soft HEAD~1            # undo the last commit, keep the changes staged

git reset --hard and git push --force discard work. Prefer the above.

Fail a chosen level on purpose and clear it through that level's course:

powershell

$env:COMPETENCY="Vaginal examination and plotting on partograph"
$env:LEVELS="5"; $env:FAIL_LEVELS="5"

6. Environment variables

BASE_URL — the one to be careful with

All three suites read BASE_URL, and in PowerShell $env:BASE_URL outlives the command that set it. A value left over from an e-kshamata run captures the next Sphere run silently.

powershell
$env:BASE_URL="https://portal-staging.aastrika.org"   # set
Remove-Item Env:BASE_URL                               # clear
Get-ChildItem Env:BASE_URL                             # check
bash
export BASE_URL=https://portal-staging.aastrika.org
unset BASE_URL

The Sphere runner now rejects a non-Sphere BASE_URL and prompts instead, rather than running Sphere specs against another portal. Clear it anyway — other entry points read it directly.

The rest

Account precedence, highest first: PROD_EMAIL / STAGING_EMAIL (whichever matches the environment) → TEST_USER_EMAIL → MONITOR_EMAIL. So a PROD_EMAIL sitting in .env wins over TEST_USER_EMAIL and the runner will say so as it starts — worth reading that line, because it explains a run that signs in as an account you did not expect.

8. Troubleshooting

A run prints the dotenv line and then nothing. Orphaned Playwright processes from a killed run are holding things up. Clear them:

powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.CommandLine -like '*EkshamataWebAutomation*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }

Run one browser workload at a time. Two headed runs on one machine make the slower one time out and report a failure that is not real.

Signup fails with "Sorry ! User not created. Please try again in sometime." The portal rejects an email whose local part (before the @) is 20 characters or longer; 19 works. testautomation + 5 digits is exactly 19, so any prefix pushes it over. The UI gives no error — the wizard just resets to a blank form, which looks like a button that never fired. The suite now shortens the base name to make room for the stage- tag, so staging produces stage-testauto12345@yopmail.com.

No OTP arrives. First check whether the account was created at all: watch POST /apis/public/v8/signupWithAutoLoginV2/register in the network panel. A 500 there means no user, and therefore no mail — the inbox being empty is a symptom, not the cause.

The competency home shows no cards. Either the account is brand new and its learning plan has not been built yet, or it is sitting on the Terms of use gate at /app/new-tnc, which blocks every route.

Playwright note: isVisible({ timeout }) does not wait — it is an instant check and the timeout option is ignored. Use waitFor({ state: 'visible', timeout }) when something needs waiting for. This caused two real bugs: a Terms gate that was never accepted, and a retry loop that reloaded 58 times in the time it should have spent watching for one element.
