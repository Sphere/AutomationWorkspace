Where the tests run

Browsers and devices

  • Chrome (Chromium) for every web suite
  • Firefox and WebKit (Safari) for a cross-browser set: public pages, search, logged-out access, unhappy paths
  • Phone and tablet screen sizes (390 × 844, 768 × 1024) inside the browser
  • Simulated slow 3G through Chrome DevTools for page-load timings

Environments

  • Production: sphere, ekshamata .aastrika.org
  • Staging: portal-staging, ekshamata-staging
  • UAT: uat, ekshamata-uat, cbp-uat
  • Localhost (port 3000), a copy of production for local work

Each environment has its own backend, so test accounts are created separately on each one. The environment is picked with one setting, BASE_URL, or from the terminal menu.

Kinds of testing covered

KindHow it is done
End-to-end user journeysOne new user signs up, then goes through My Courses, course completion, competencies and Account, all in one run.
API testingCalls the portal's Sunbird and Keycloak APIs directly: creating users, assigning roles, enrolments, progress, passbook and answer keys.
Checking results, not just screensCompares what the page shows with what the API returned (search results, course completion, certificates).
Unhappy pathsWrong password, wrong OTP, unregistered email, duplicate signup and forgot-password errors.
Access controlPrivate pages and APIs are opened with no login to make sure nothing private leaks.
Environment comparisonProduction compared with staging or UAT, side by side: course counts, organisation content and page differences.
Cross-browserThe same tests in Chrome, Firefox and Safari's engine.
Page-load timingsTime to main content on a normal and a slow 3G connection, recorded to a CSV after every run.
Production monitoringA small check of login and the signed-in app, three times a day, on production and UAT.
Two languagesEvery label check accepts English or Hindi, using the portal's own translation file.

Running on its own: GitHub Actions

Seven workflows run the suites without anyone at a keyboard. Results arrive as GitHub's notification emails.

WorkflowProjectWhen it runs
env-compare-daily.ymlSphereEvery day: tests and signup on each environment, then the comparison and one combined report
prod-monitor.ymlSphereThree times a day on production and UAT
staging-deploy-tests.ymlSphereAfter a staging or UAT deployment, or by hand
prod-deploy-tests.ymlSphereAfter a production deployment, or by hand
regression.ymlSphereBy hand, for a full regression after a release
daily.ymle-KshamataEvery day: journey, organisation checks and comparison
daily-lifecycle.ymlCBPEvery day on staging; UAT when chosen

Manual runs offer an Environments choice (production only, production + staging, UAT only, or all three). Passwords and tokens live in GitHub Secrets, never in the code. Reports are kept for 90 days and can be copied to the PC with npm run reports:pull.

Reports

After every run

  • Playwright's HTML report, with screenshots, videos and step traces for failures
  • A branded HTML report and a matching Excel workbook (results, steps, console output)
  • Environment comparison reports in HTML and PDF
  • Page-load timings in test-reports/page-timings.csv

Daily, from GitHub

  • One combined summary of every job and environment
  • Headline results shown as notices on the run, so they appear in GitHub's email
  • A list of the differences found between environments
  • A record of every test account created

How the code is organised

Shared building blocks

  • Page objects for screens like the course player
  • Fixtures that log in once and hand every test a signed-in browser
  • Helpers for login, OTP reading, signup, profile forms and translation
  • An organisation registry with each organisation's roles and language
  • An API client to create users and check progress directly

Ways to run it

  • npm run go: a terminal menu to pick the environment and tests
  • npm run compare: compare two environments side by side
  • npm run forgot: reset a test account's password
  • npm run test:browsers: Firefox and Safari runs
  • npm run i18n:update: refresh the Hindi label dictionary

What a full run does

Pick an environmentProduction, staging or UAT, from the menu or GitHub
Create a new userSignup with a YOPmail address, OTP read automatically
Walk the journeyMy Courses, finish a course, climb competency levels, Account
Check the recordsPassbook, enrolments and certificates confirmed through the API
